## 확정한 것 (사용자 결정 2026-10-08)
- **전용 대시보드**를 새로 만든다. 기존 그로홈 대시보드·CRM에는 넣지 않는다.
- **Firebase는 기존 pour-app-new를 쓴다.** 컬렉션 이름은 모두 `mkt-`로 시작한다. 다른 앱 규칙은 건드리지 않는다.
- **CSV 정리는 관리자 화면에서 한다**(무료, Cloud Function 없음). Aside는 올리기만 하고, 관리자가 대시보드를 열면 쌓인 업로드를 정리한다. 열기 전까지는 정리 전 상태다.
- 권한은 Admin SDK 커스텀 클레임 대신 **역할 문서 `mkt-access/roles`**로 둔다. 소싱앱 `sourcing-access/roles`와 같은 방식이고, 서비스 계정 키가 필요 없다.

## ⚠️ 지금은 임시 저장소 (2026-10-08 ~ 규칙 게시 전)
- 대표님이 휴대폰 인증 문제로 **10-12(월)까지 Firebase 콘솔에 못 들어가서** 보안 규칙을 게시할 수 없습니다. 그래서 **이미 게시된 공개 규칙 안(`pour-os/marketing-hub/<컬렉션>`)**에 저장합니다. 그로홈 대시보드 데이터가 있는 곳과 같은 공간이고, 사용자 결정(2026-10-08 "규칙 없이 지금 쓰기")에 따른 것입니다.
- 이 기간엔 **주소를 아는 사람은 기술적으로 읽고 고칠 수 있습니다.** 권한(관리자·업로더)은 화면에서만 확인합니다.
  - 그래서 업로드 원본 CSV는 **알아본 열만 저장**합니다. 고객 이름·전화 같은 다른 열이 있어도 버립니다.
  - Aside에는 **주문 목록 말고 상품별 통계·광고·재고 리포트**만 올리게 합니다.
- **규칙 게시 후 전환 순서**
  1. 콘솔에서 `firestore.rules` 게시
  2. `core.js` `STORE_MODE`를 `'secure'`로 바꿔서 커밋 (Claude가 함)
  3. 대시보드 설정 › **[임시 저장소에서 옮기기]**: 판매·광고·재고·업로드 기록·계정·기준값·고객의 소리·AI 팀 기록을 복사합니다. 임시 저장소는 지우지 않고, 원본 CSV는 옮기지 않습니다.
- 로그인 화면의 **[비밀번호 재설정 메일]**과 **[처음이면 대표 계정 만들기]**(대표 이메일만)는 콘솔 없이 씁니다.

## 계산식 (`core.js`)
- **재고(레오)**
  - 일평균 = 최근 14일 판매수량 ÷ 14 (모든 채널 합)
  - 남은 일수 = 가용재고 ÷ 일평균
  - 남은 일수 ≤ 리드타임 + 안전재고(7일)이면 발주
  - 발주 수량 = (리드타임 + 30일) × 일평균 − 가용재고
- **키워드(케이)**: 최근 7일 합계로 판단한다.
  - 끄기: 비용이 1만원 이상인데 전환매출이 0
  - 줄이기: ROAS 200% 미만
  - 올리기: ROAS 400% 이상이고 클릭 10회 이상
  - 기준값은 모두 대시보드 ⚙️ 설정에서 바꾼다.
- **채널별 열 이름**은 `core.js`의 `FIELDS`에 있다. 실제 CSV 샘플을 받으면 거기만 고친다.
