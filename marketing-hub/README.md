> 사용자 작업지시서(2026-10-08 claude.ai 대화 정리)를 이 폴더에서 구현한 것. 옵시디언 볼트(`POUR 마케팅 허브.zip`)는 글(제품 카드·작업 기록)을, 이 대시보드는 매일 바뀌는 숫자(판매·광고·재고)를 쌓는다.

업로더 계정이 대시보드 주소로 들어오면 자동으로 올리기 화면으로 보낸다(직원은 임시 저장소 기간엔 고객의 소리 화면으로 · 잠긴 뒤엔 voc.html 주소로 바로). 실제 차단은 보안 규칙이 한다.

## 확정한 것 (사용자 결정 2026-10-08)
- **전용 대시보드**를 새로 만든다. 기존 그로홈 대시보드·CRM에는 넣지 않는다.
- **Firebase는 기존 pour-app-new를 쓴다.** 컬렉션 이름은 모두 `mkt-`로 시작한다. 다른 앱 규칙은 건드리지 않는다.
- **CSV 정리는 관리자 화면에서 한다**(무료, Cloud Function 없음). Aside는 올리기만 하고, 관리자가 대시보드를 열면 쌓인 업로드를 정리한다. 열기 전까지는 정리 전 상태다.
- 권한은 Admin SDK 커스텀 클레임 대신 **역할 문서 `mkt-access/roles`**로 둔다. 소싱앱 `sourcing-access/roles`와 같은 방식이고, 서비스 계정 키가 필요 없다.

## ⚠️ 지금은 임시 저장소 (2026-10-08 ~ 규칙 게시 전)
- 대표님이 휴대폰 인증 문제로 **10-12(월)까지 Firebase 콘솔에 못 들어가서** 보안 규칙을 게시할 수 없습니다. 그래서 **이미 게시된 공개 규칙 안(`pour-os/marketing-hub/<컬렉션>`)**에 저장합니다. 그로홈 대시보드 데이터가 있는 곳과 같은 공간이고, 사용자 결정(2026-10-08 "규칙 없이 지금 쓰기")에 따른 것입니다.
- 이 기간엔 **주소를 아는 사람은 기술적으로 읽고 고칠 수 있습니다.** 권한(관리자·업로더)은 화면에서만 확인합니다.
  - 그래서 업로드 원본 CSV는 **알아본 열만 저장**합니다. 고객 이름·전화 같은 다른 열이 있어도 버립니다.
  - Aside에는 **주문 목록 말고 상품별 통계·광고·재고 리포트**만 올리게 합니다.
- **규칙 게시 후 전환 순서**

  2. `core.js` `STORE_MODE`를 `'secure'`로 바꿔서 커밋 (Claude가 함)
  3. 대시보드 설정 › **[임시 저장소에서 옮기기]**: 판매·광고·재고·업로드 기록·계정·기준값·고객의 소리·AI 팀 기록을 복사합니다. 임시 저장소는 지우지 않고, 원본 CSV는 옮기지 않습니다.
- 로그인 화면의 **[비밀번호 재설정 메일]**과 **[처음이면 대표 계정 만들기]**(대표 이메일만)는 콘솔 없이 씁니다.

## 데이터 (pour-app-new)
| 컬렉션 | 내용 | 권한 |
|---|---|---|

| `mkt-sales/{날짜}_{채널}_{상품코드}` | `qty, revenue, orders, productCode, productName` | 관리자 |
| `mkt-ads/{날짜}_{채널}_{해시}` | `campaign, keyword, impressions, clicks, cost, revenue, roas` | 관리자 |
| `mkt-stock/{날짜}_{상품코드}` | `available, avgDailySales, daysLeft, leadTimeDays, reorderNeeded, reorderQty` | 관리자 |
| `mkt-settings/main` | 리드타임·안전재고·ROAS 기준 등 | 관리자 |
| `mkt-voc/{자동}` | 고객의 소리 `{product, type(불만/문의/요청/칭찬/하자·안전), source, text(개인정보 가림), masked, urgent, date, by, byEmail, createdAt, resolved}` | 직원·관리자 **새로 만들기만**(직원) · 읽기/끝남 표시는 관리자 |
| `mkt-team/{팀원 id}` | AI 팀 검토 기록 `{lastDate, lastTitle, lastNote, reviewed}` | 관리자 |
| `pour-os/v2/links/mkt-*` | 업무OS '확인할 것' 한 줄 (src `mkt` · kind `aiReview`/`voc`/`publish`(발행) · **내용·개인정보 없음**) | 공개 규칙(업무OS 다리 · CRM 다리와 같은 곳) |
| `pour-os/marketing-hub/mkt-notes/{검토 줄 id}` | AI 팀원 노트 본문(마크다운) + 대표 메모 `memo/memoAt/memoBy` | 늘 공개 자리(루틴은 로그인 없음 · 게시할 원고라 원가·개인정보 없음) |
| `pour-os/marketing-hub/mkt-posts/{노트 id}~{n}` | 게시할 글 한 편 `{noteId, n, member, date, channel, heading, title, titleB, tags, thumbs, notice, body, plain, products, brand, status, failNote, url, queuedBy/At, draftBy/At, publishedBy/At}` · status `queued`(Aside 대기) → `draft`(임시저장됨) → `published`(사람이 발행) · `failed` · `canceled` | 늘 공개 자리 |
| `pour-os/marketing-hub/mkt-config/channels` | 채널 글쓰기 주소 `{naver_blog, tistory, cafe(줄마다 "이름\|주소")}` | 늘 공개 자리 |
| `mkt-products/{상품코드}` | (예정) 제품 87개 마스터 · 옵시디언 `제품코드`와 같게 | 관리자 |

- **같은 날짜·채널을 다시 올리면 그날 데이터를 통째로 바꾼다.** 같은 ID는 덮어쓰고, 새 리포트에 없는 줄은 지운다. 루틴이 두 번 돌아도 중복이 생기지 않는다.
- 상품코드가 없는 리포트는 상품명으로 묶는다(`name:상품명`).
- CSV가 900KB를 넘으면 알아본 열만 남겨서 저장한다(`reduced: true`).
- 한국 관리자 사이트의 EUC-KR CSV도 읽는다.

## 계산식 (`core.js`)
- **재고(레오)**
  - 일평균 = 최근 14일 판매수량 ÷ 14 (모든 채널 합)
  - 남은 일수 = 가용재고 ÷ 일평균
  - 남은 일수 ≤ 리드타임 + 안전재고(7일)이면 발주
  - 발주 수량 = (리드타임 + 30일) × 일평균 − 가용재고
- **키워드(케이)**: 최근 7일 합계로 판단한다.
  - 끄기: 비용이 1만원 이상인데 전환매출이 0
  - 줄이기: ROAS 200% 미만
  - 올리기: ROAS 400% 이상이고 클릭 10회 이상
  - 기준값은 모두 대시보드 ⚙️ 설정에서 바꾼다.
- **채널별 열 이름**은 `core.js`의 `FIELDS`에 있다. 실제 CSV 샘플을 받으면 거기만 고친다.
